# Character Continuity v2.02-test-fm-instructions notes

This test release changes how Character Continuity reaches the model. It does not change the creator-owned source-card formats or the validated CCO update protocol.

## What changed

- CC creates one generated `CC — Model Context — Name` Story Card for each activated NPC.
- That card normally uses the canonical name and unambiguous Active aliases as native triggers; a currently mentioned managed alias can be added transiently so Emerging, Retired, or Rejected status remains available when needed.
- Its Entry is a bounded portrayal projection: compact Outer and Inner, then complete optional blocks that fit for current State, Turning Point stage, Relationships, Views, Names, and one Experience.
- Source and storage cards retain internal keys and do not become ordinary scene-triggered lore.
- A complete current assessment or operation packet is appended to ordinary Context inside `<CC_CONTEXT_PACKET>...</CC_CONTEXT_PACKET>`.
- Front Memory contains only a short mandatory-compliance instruction or prose-recovery instruction; it contains no evidence, target map, mechanics, or CCO templates.
- Ordinary no-task turns contain no CC Front Memory block.
- CC owns only the text between `<CC_FRONT_MEMORY>` and `</CC_FRONT_MEMORY>` and preserves surrounding Front Memory.
- An operation is marked delivered only after the returned Context verifies the complete packet and both the returned context and `state.memory.frontMemory` verify the short instruction.
- The appended operation-packet ceiling is 700 estimated tokens. A generated Model Context card is capped at 4,400 characters.

## Safe test procedure

1. Duplicate the Scenario or preserve the four installed v2.01 script tabs.
2. Replace Library, Input, Context, and Output with the four files in this package.
3. Keep `// @cache-compatible` as the first Context line.
4. Start a fresh Adventure for the cleanest comparison.
5. Enter an action that mentions one activated NPC by canonical name.
6. Confirm that exactly one `CC — Model Context — Name` card exists and its keys include the name.
7. Open the Context Viewer. The generated card should appear when its name triggers; CC should not append a second full portrayal packet at the end.
8. On an assessment turn, confirm that Context contains one complete `<CC_CONTEXT_PACKET>`, Front Memory contains the short instruction but no Evidence rows or CCO forms, and `CC — Status` reports `Front Memory: operation | verified Yes` with a packet at or below 700 tokens.
9. After Output, check that CC reports `Front Memory: clear` and that any unrelated Front Memory text remains.
10. Confirm that no `(CCO|...)`, `<CC_FRONT_MEMORY>`, or `<SYSTEM>` control text appears in visible story.

## What to report from a failed case

Enable `Debug: true` for one action and preserve:

- the complete generated output before manual editing;
- `CC — Status`;
- all `CC — Debug` pages;
- the affected NPC's generated Model Context card;
- whether the action was Input, Continue, Retry, or Context Viewer refresh; and
- whether another script also edits Context or Front Memory.

If `Front Memory instruction verification failed` appears, check that CC runs last among Context functions that append or replace suffix text and that another script has not placed text after the current `state.memory.frontMemory` value.

## Rollback

Restore the four v2.01 script tabs, then remove only the generated cards whose keys begin `__CC_MODEL_CARD__:`. v2.01 does not maintain them, but their name triggers would otherwise remain active. Do not remove creator source cards or managed State, Names, Relationships, Views, Turning Points, or Experiences cards.

## Included automated check

Run from the package directory:

```sh
node tests/hybrid-memory.test.js
```

The test exercises generated triggering, Active-versus-Rejected alias keys, the card-size bound, exact preservation of unrelated Front Memory, separation of the complete Context packet from the short Front Memory instruction, verified suffix replacement, duplicate prevention, crowded-context deferral, assessment delivery under the 700-token ceiling, frozen-evidence carry, prose recovery, hidden-record stripping, Output cleanup, disabled-mode cleanup, and safe refusal when Front Memory is not the actual suffix.
