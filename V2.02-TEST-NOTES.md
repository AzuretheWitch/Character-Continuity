# Character Continuity v2.02-test-b5 notes

This test release replaces the separate stable Outer/Inner portrayal route for newly created NPCs with one compact Essentials card. The b4 transport, liveness, one-owner/one-family scheduling, and 600-token operation-task ceiling remain in place.

## What changed in b5

- A new NPC receives four visible onboarding cards: `Name's Essentials`, `Name's Views`, `Name's Relationships`, and `Name's Experiences`.
- Essentials combines Outer and Inner fields, starting status, canonical identity, and optional onboarding alias records in one creator-visible form.
- Required Essentials fields are `Name, age, gender, pronouns`, `Race/Species`, `Physical attributes`, `Personality`, `Wants`, `Principles`, and `Starting status`.
- `Clothing style`, `Mannerisms`, `Fears`, and `Mental wounds` are optional. Blank optional lines are removed on activation.
- Essentials has a 1,000-character hard ceiling and an 850-character preferred target. An oversized pending draft is preserved for correction; CC does not truncate it or add an ellipsis.
- `Name's Names` and `Name's State` are not created while onboarding is pending. Successful activation creates both managed cards transactionally.
- Optional Alias/Status/Use/Progress/Reason groups in the pending Essentials form seed the authoritative Names ledger. Active Essentials then shows only a compact mirror, for example `Active [General]: Frost` or `Rejected: Fox`.
- The activated Essentials card is itself name-triggered and supplies stable portrayal. Its canonical name and unambiguous Active aliases are ordinary native triggers; the private marker preserves card identity.
- `CC — Model Context — Name` now contains only the player-agency reminder and complete relevant dynamic blocks for current State, Turning Point development, Relationship, View, or Experience. It contains no Essentials portrayal and no Names.
- Dynamic Model Context prefers at most 600 characters and has a 1,000-character hard ceiling. Lower-priority blocks are omitted whole instead of clipped.

## Legacy compatibility and migration

- Completed legacy Outer/Inner NPCs remain readable and playable.
- When b5 finds a legacy roster NPC without Essentials, it creates a pending Essentials migration draft. If a valid compact conversion fits, it prefills the draft; otherwise it creates a blank safe template.
- Legacy Outer, Inner, Names, and other source cards remain active while migration is pending and are not deleted after approval.
- The creator reviews and compacts the draft, then changes `Ready: No` to `Ready: Yes`. Only a valid Essentials card at or below 1,000 characters activates.
- A six-card onboarding pack that was already pending under an older build continues through the legacy onboarding route rather than being stranded.
- Existing completed Essentials cards are preserved. CC refreshes only their compact Names mirror and managed keys when the authoritative Names ledger changes.

## Transport and scheduling retained from b4

- Front Memory contains only a current task, a prose-recovery task, or an unpromoted possible-next task staged for Continue. Ordinary no-task turns contain no CC block.
- CC owns only text between `<CC_FRONT_MEMORY>` and `</CC_FRONT_MEMORY>` and preserves surrounding Front Memory.
- Input and Output prepare tasks before platform context assembly. Enabled Context verifies the exact complete suffix byte-for-byte; it does not append, resize, or truncate the task.
- Each response authorizes at most one operation family for one fixed active NPC. Owner/family drain and fairness rotate Name, State, Relationship, View, and Turning Point work without reducing the five-NPC roster ceiling.
- The operation-task payload hard ceiling remains 600 estimated tokens. Normal tasks target 592 to reserve Retry headroom.
- Output strips accepted, unchanged, stale, rejected, malformed, cut-off, and omitted control material before returning visible story prose.

## Safe test procedure

1. Duplicate the Scenario or preserve the four installed v2.01 script tabs.
2. Replace Library, Input, Context, and Output with the files in this package.
3. Keep `// @cache-compatible` as the first Context line.
4. Start a fresh Adventure and add a new canonical name to `CC — Active NPCs`.
5. Confirm that exactly four pending setup cards appear and that neither Names nor State exists yet.
6. Fill the seven required Essentials fields, leave at least one optional field blank, optionally add an alias, and keep the entire Entry at or below 1,000 characters.
7. Set `Ready: Yes`, continue once, and confirm activation created Names and State, removed onboarding controls and blank optional lines, and produced compact name lines in Essentials.
8. Mention the NPC by canonical name or an unambiguous Active alias. Confirm Essentials supplies portrayal and the generated Model Context card contains only agency/dynamic continuity, at no more than 1,000 characters.
9. Confirm `CC — Status` reports the Essentials and Model Context counts and that any staged operation task is at or below 600 estimated tokens.
10. Confirm no `(CCO|...)`, `<CC_FRONT_MEMORY>`, or `<SYSTEM>` control text appears in visible story.

For migration testing, load an NPC with completed legacy Outer/Inner cards, confirm that b5 creates a pending Essentials draft without deleting or disabling the legacy sources, then approve the draft after review.

## What to report from a failed case

Enable `Debug: true` for one action and preserve:

- the complete generated output before manual editing;
- `CC — Status` and all `CC — Debug` pages;
- the affected Essentials, Names, and generated Model Context cards;
- any legacy Outer/Inner cards involved in migration;
- whether the action was Input, Continue, Retry, or Context Viewer refresh; and
- whether another script also edits Context or Front Memory.

## Rollback

Restore the four v2.01 script tabs, then remove generated cards whose keys begin `__CC_MODEL_CARD__:`. Also archive each Essentials card or remove every ordinary name trigger after its first private `__CC_ESSENTIALS__:` marker; v2.01 does not maintain those triggers, so leaving them active can duplicate legacy portrayal. Preserve the Essentials Entries and all legacy Outer/Inner, State, Names, Relationships, Views, Turning Points, and Experiences cards for recovery.

## Included automated checks

Run from the package directory:

```sh
node tests/essentials-card.test.js
node tests/hybrid-memory.test.js
node tests/blocker-one-liveness.test.js
node tests/assessment-family-fit.test.js
node tests/retry-lifecycle.test.js
```

The Essentials checks cover four-card onboarding, pending privacy, required-field validation, optional blank removal, the 1,000-character hard ceiling, oversize preservation without ellipsis, compact Active/Rejected alias routing, legacy migration behavior, and portrayal-free dynamic Model Context. The retained checks cover Front Memory preservation and verification, Continue/Retry lifecycle, owner/family drain rotation, five-active-NPC support, cross-family rejection, Retry headroom, and the 600-token task ceiling.
